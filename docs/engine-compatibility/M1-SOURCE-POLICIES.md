# Component policies exercised by the source T-90M

These optional `components-v1` fields extend the [base authoring contract](M1-M2-AUTHORING.md). They are data policies shared by any definition pack. The actual playable binding lives in `mods/usgr-re/mod.json`, generated by `component_port.py`; no engine code names that pack or unit.

## Accumulated damage and carried ammunition

A part's `hp` is its functional threshold. `damageLimit` optionally permits accumulated damage above that threshold (bounded at one million). `stockThreshold` names local `logistics-v1` stocks and adds `perMissing * (capacity - amount)` to the threshold. `strict` uses `>` instead of `>=`. The limit must permit the maximum possible threshold. Save restoration validates the failure flag after all modules have restored, so depleted inventory is read from the save rather than the newly constructed match. `rebaseOnRefill` subtracts the removed empty-stock allowance from accumulated damage **before** those stocks refill. This can leave negative damage; it is saved as such and displayed with a clamped health fraction. Repeated partial transfers do not invoke this full-refill policy.

`damagedBelow` bounds a wound effect's damage window. `latchDamaged` retains the wound effect after entering that window until explicit repair, even if subsequent damage crosses its upper end. `failure.destroy` uses the common kill lifecycle. An optional definition `failureDelay` delays the attributed death while immediately blocking weapons/movement. Optional `failure.hullRange` draws the pre-death HP from the seeded simulation RNG. Terminal clocks continue under EMP and transport. Private network views redact a hidden killer's ID and weapon; authoritative saves retain attribution.

## Crew pool and repair

`reserve` is a finite count plus pooled health, separate from the named crew seats. Its `channel`, `exposure`, `damageHp`, `hpPerMember`, `roundHealth`, and optional blast bands define casualty arithmetic. A penetrating channel hit recomputes `min(oldCount, max(0, floor(health / hpPerMember)))`; a blast can author a different `poolCountOffset`. Replacement fills the first empty seat in `priority` after `seconds`, consumes one count, creates a distinct identity and retains the remaining pool's health. Replacement progress pauses during a crew refill service. `empty` applies effects when the count is zero. `refillCosts` allows each dead seat to consume an authored number of replenished reserve members; surviving injured seats are retained. A crew-only terminal condition requires both all seats empty and no reserve count.

`crew.requiresEmptyReserve` restricts manual seat transfers to an empty pool. `vacatedDamage` sets the vacated seat's damage fraction (default 1). Transfers retain the living person's identity and proportional injury.

`repairGroup` replaces independent part tasks with one fixed-interval clock. `priority` contains existing `partId/policyIndex` references. Automatic policies can advance it; manual policies require the `repair` action with choice `group` and an allied provider in the group's range. Per-part command choices are rejected for a grouped definition. A policy's `startAbove` makes clock advancement strict, while completion still uses `fromDamage`. `untilDamage` is an exclusive upper bound. Individual provider requirements pause eligible clock advancement when unavailable; they do not erase shared progress. `floorOnHit` truncates retained progress after a penetrating non-blast hit. Blast damage does not interrupt the group clock.

Optional `finishBelow` completes the manual session only when every part is below that fraction and the group provider is in range. Completion resets residual damage and wound latches. `refillProtection` also restores all authored layers. Starting a manual session requires an actual eligible wound, so healthy units cannot use it as an instant armor refill. Optional `beginRefill` names a crew refill service: starting repair requests it only when the reserve or active seats need replenishment, through the same allied provider, range and active-service checks as the supply command. Healthy or unrelated recipients cannot start a crew refill through UI, CLI or this bridge. Paid individual policies are rejected with shared repair groups.

`turnFromSpeed: [offset, scale]` derives the relative turn multiplier as `offset + scale * composedMovementMultiplier`. `clearOrdersWhenImmobile` clears movement orders while component damage or shared repair immobilizes the entity. These policies act only on participating mod entities.

## Protection and blast payloads

`rangeOrigin: "source"` evaluates the range polynomial from the firing entity's current position at impact; the saved launch position is the fallback if it no longer exists. The default remains the saved launch origin. `wearFaces` redirects layer wear independently of the struck protection face. `layerScale` scales each struck layer before penetration. Channel `faces` overrides independent strong/weak ranges by impact face. `collateralHullDamage` explicitly handles collateral hits on compatible component recipients, while targets without that protection family retain their native HP damage.

A projectile `blast` contains `yield`, world-pixel `radius`, `poolCountOffset`, and optional `penetration` (default false). Recipient `blast` specifies a protection family and computes:

```
pressure = base / (base + armorScale * basePlate)
           * coefficient * yield² / max(minimumDistance², distance²)
```

This uses base plate, not consumable layers. Each part/pool chooses the first descending blast band with `pressure > above`. The damage range is multiplied by part HP (`part`), pressure × HP (`pressure-part`), or yield × pressure × HP (`yield-pressure-part`). Damage rolls use the match RNG. A shield absorbs the event's component energy once; hull damage remains separately authored.

## Actual acceptance and limits

`mods/usgr-re/components-game.test.ts` loads the published manifest and checks native projectile impacts, ERA depletion, AP component failure and attributed delayed death, HE track damage and recovery, finite crew replacement, shared repair, inventory-dependent rack survival, save continuation and private output. `test_component_port.py` checks source extraction and atomic omission when inventory or payload provenance is incomplete.

The mapping is an initial-rank AP/HE core, not an RW script interpreter. It omits experience/achievement modifiers, dynamic source weak-hit accuracy, helper retargeting, penetration fragments, HE forest radius switching, ATGM/HEAT component payloads, abandonment and source cosmetic kill effects. Stable movement penalties are derived from current parts rather than transient flag ordering; driver replenishment's sub-0.1-second speed reset is not reproduced. See the pack's [current source boundaries](../../mods/usgr-re/COMPONENT-GAPS.md).
